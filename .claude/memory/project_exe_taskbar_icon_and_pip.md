## Taskbar icon bug (fixed 2026-06-07)

Symptom: installed exe showed the default **Electron logo in the Windows taskbar**, while the title bar and tray showed the correct Greencaller logo.

Root cause: `public/app-icon.ico` (and `build/icon.ico`) were generated by `png-to-ico`, which embeds **every** size (16/32/48/...) as a **PNG-encoded** entry. Electron's own decoder renders PNG-in-ICO fine (so title bar + tray were correct), but the Windows **shell** (taskbar button + the icon rcedit embeds into the .exe) needs the small sizes as classic **BMP/DIB**. All-PNG ⇒ shell falls back to the default Electron icon.

Fix: `greencallerapp1exe/scripts/generate-icon.cjs` re-encodes the ICO from the existing 256px master — 16/32/48/64/128 as 32-bit BMP, 256 as PNG. Run `node scripts/generate-icon.cjs` if the icon is ever regenerated. **Do NOT regenerate with `png-to-ico`** — it reintroduces the bug.

### The deeper cause: contaminated AppUserModelID (fixed 2026-06-10)
Even after the icon re-encode + icon-cache flush, the taskbar STILL showed the Electron logo (but tray showed Greencaller — the tell-tale sign). Root cause: `main.ts` set the SAME AUMID `com.greencaller.app` in dev and prod, so every `npm run electron:dev` run of the unbranded `node_modules\electron\dist\electron.exe` registered the Electron icon/jumplist against that AUMID. Windows caches the taskbar icon + jump list **per-AUMID** in a store that survives `IconCache.db` deletion and reboots.
Fixes applied:
1. Dev/prod AUMID split: `app.setAppUserModelId(app.isPackaged ? "com.greencaller.desktop" : "com.greencaller.desktop.dev")`.
2. **Changed the desktop AUMID + electron-builder `appId` from `com.greencaller.app` → `com.greencaller.desktop`** (a brand-new identity the Electron runtime never touched), bumped version 0.0.0 → 0.0.1, rebuilt + reinstalled. This abandons the contaminated AUMID entirely.

IMPORTANT distinction the user cares about: `com.greencaller.app` is ALSO used as the iOS bundle ID / Android package / Telnyx push identifier — but those live in a SEPARATE mobile repo (NO ios/android/capacitor folders exist in greencaller1). The Windows AUMID is desktop-only and shares only the string; changing it does NOT affect mobile/Telnyx. In greencaller1, `com.greencaller.app` appeared ONLY in `greencallerapp1exe/electron/main.ts` and `greencallerapp1exe/package.json` (build.appId).
Also: clearing the per-AUMID cache requires the app FULLY CLOSED during `ie4uinit.exe -ClearIconCache` + Explorer restart (flushing while it runs re-caches instantly).

## Native floating call PiP (Electron only)

Google-Meet-style mini call card that floats over OTHER apps. Triggered by a "Pop out" (PictureInPicture2) button added to `ActiveCallPanel` and `ActiveCallModal` (button is electron-guarded via `window.electronAPI?.isElectron`).

- Native window lives in `electron/main.ts` (`createCallPip`/`hideCallPip`, alwaysOnTop screen-saver level, skipTaskbar, transparent, frameless). Separate from the incoming-call `overlayWindow`.
- It does NOT own the call — buttons send `pip-action` (mute/hold/end/maximize) to the renderer, which calls the existing `toggleMute/toggleHold/endCall`. Renderer pushes state back via `update-call-pip`. Bridge lives in `src/hooks/useCallPip.ts`.
- Pages (`Dashboard.tsx`, `EnterprisePlatform.tsx`) own `isPipActive` state; when true the in-app Sheet/modal are hidden. Maximize restores window + panel view.

Related: [[project_structure]] — these component edits are exe-only and were NOT synced to the web app (the changes are web-safe since the button is electron-guarded).
